Dev Tools

One development dashboard, dropped into a page with a single <script> line. No build, no stylesheet, no dependency: the UI comes along inside a shadow root, and nothing is fetched from anywhere at runtime — the QR code is encoded in the page itself. It answers questions about the page you are building, and it never ships with it.

1 dashboard · 5 tools · 2 planned

The dashboard

One file, one bar along the bottom edge

  • dev_dashboard Page info, a11y, overflow, QR and srcset in one bar

What sits in the bar

One icon per question, one panel where it needs room

  • page information Viewport size and the four project tokens, read out permanently
  • a11y inspector Missing names, labels and semantics — green mark, or red with a count
  • horizontal overflow What is wider than the document, and by how much
  • QR code This URL on a device, encoded in the page — no request leaves
  • srcset measurement Measures sizes/srcset over a viewport sweep in a probe frame

What the bar could answer next

  • asset weight planned What the page actually loaded, by type

Every component demo loads this one script — it replaced the two dev_ aids that used to live in src/_shared/js/. dev_pageInfo is the bar's read-out, dev_qrCode is its QR panel, and the API it went to for the image is gone: the code is encoded locally, so the dashboard makes no third-party request at all. docs/toolStandards.md holds the rules a tool follows, the readme holds how this one is operated.
