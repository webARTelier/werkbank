autoGrowTextarea

A textarea that is as tall as what is written in it — no half-empty box, no inner scrollbar until it has to be one.

This engine sizes the field itself. It has field-sizing: content, so everything below is CSS — autoGrowTextarea.js sets its ready attribute and returns without registering a single listener. Switch scripting off and nothing changes.

This engine needs the module. It has no field-sizing: content, so autoGrowTextarea.js measures each value and hands the height to the stylesheet as a length. Switch scripting off and the fields stay at their rows height, with a scrollbar and a resize handle.

The default: three lines, growing to twelve

Type into it. The field starts at three lines — the same three its rows attribute states, so the first paint is already right — and follows the value line by line up to twelve. The count is in lh, the height of one line box of this field, so it follows the page's typography instead of a number somebody guessed.

Three lines to start with, twelve at most.

A value that is already there

The same field, rendered with a value in it — a draft loaded from a CMS, a form coming back from a failed validation. It is the right height on arrival: in this engine's lane either the stylesheet had it from the first paint, or the module measured it in its constructor, before any frame it could have been seen in.

A tighter cap: one line, at most five

--autoGrowTextarea-min-rows: 1 and --autoGrowTextarea-max-rows: 5, set on this one instance. It starts as a single line and stops growing at five — and then scrolls, because the cap is a maximum and not a lid: keep typing and every line stays reachable. A field that grew without limit would push the button below it off the screen instead.

No cap, and a column that changes width

--autoGrowTextarea-max-size: none takes the cap off entirely. Drag the dashed box narrower by its bottom-right corner: the value rewraps into more lines and the field gets taller, because how tall a text is was never a property of the text. In the module's lane that is what the ResizeObserver is for — the field's own width is the signal, not the window's.

Inside a form: resetting the value

A form reset puts the authored value back without firing an input event — the one value change the module cannot hear. So it listens for reset on the form itself and measures again on the next frame. Type something, then press Reset: the field returns to the draft above and to that draft's height.

Two modules on one field

data-js-behavior="autoGrowTextarea,inputCharCount" — the loader runs both, in source order, on the same element. The counter counts down from the native maxlength, the box follows the value, and neither knows about the other: one behaviour per module, composed in the markup.
